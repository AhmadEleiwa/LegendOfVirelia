## World coordinates

`Chunk` dimensions are 16 × 96 × 16. X/Z choose a chunk; Y is vertical. `World` converts world coordinates with `Math.floorDiv` and `Math.floorMod`, including for negative positions.

```java
int chunkX = Math.floorDiv(worldX, Chunk.SIZE_X);
int localX = Math.floorMod(worldX, Chunk.SIZE_X);
```

`World` owns chunks, block edits, fluid state, and generation. It does not draw. `Chunk` stores block IDs, sunlight, block light, and fluid metadata.

## Add a block

1. Add a supplier to `Blocks`.
2. Add `assets/models/<name>.json` and matching texture if needed.
3. Register it before world generation.
4. Add a hotbar entry only if players should select it.

```java
// Blocks.java
public static final Supplier<Block> GRANITE = () -> new Block("granite");

// ClientGameLogic.init (before generating/reading block IDs)
BlockRegistry.register("granite", Blocks.GRANITE.get());
int graniteId = BlockRegistry.getId("granite");
```

IDs are assigned sequentially at runtime; they are not stable save/network IDs. A real network or save format should use a stable registry mapping.

## Block properties

`Block` extends `GameObject`, loads a named model, and exposes transparency and light emission. A torch uses `new Block("torch", 15)`. `FluidBlock` marks itself transparent and adds flow-level/timer behavior. Air is block ID `0` and has no `Block` instance.

Transparent blocks need deliberate meshing and render-pass behavior. Water is generated by `ChunkMesher` as a separate mesh and drawn through `WaterRenderer`; see [5. Rendering and meshes](rendering-pipeline.md).

## Lighting and edits

`ChunkLightingSystem` propagates sunlight and block light. After a confirmed edit, the client updates affected lighting and queues the edited chunk plus boundary neighbors for remeshing. If a new block property changes appearance, ensure the edit invalidates every chunk whose mesh depends on it.

Detailed block asset steps: [6. Shaders, textures, and models](shaders-textures-models.md). API class map: [7. API and class reference](api-reference.md).

## Usage example (pseudocode): add a custom block

**Pseudocode only.** The project’s exact registration belongs in `Blocks` and `ClientGameLogic.init`.

```text
class EntityBlock extends Block:
    constructor:
        load model "entity_block"
        set transparent = false
        set light level = 0
        attach block-specific behavior if needed

Blocks:
    ENTITY_BLOCK = supplier that creates EntityBlock

Startup, before world generation:
    BlockRegistry.register("entity_block", ENTITY_BLOCK.get())
```

For a regular model-backed block, use the simpler existing pattern: `ROCK = () -> new Block("rock")`, plus matching model and texture files.
